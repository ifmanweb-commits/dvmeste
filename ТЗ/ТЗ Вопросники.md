# Техническое задание: Новый тип испытания — Вопросник (Questionnaire)

## 1. Общее описание

Вопросник — это тип испытания, где психолог отвечает на вопросы в свободной текстовой форме. Ответы проверяются супервизорами (один или несколько). Проверка проходит по тем же правилам, что и квалификационные работы: последовательная проверка, пороговое принятие.

enum QuestionnaireStatus {

model QuestionnaireSubmission {

## 4. Логика работы

### 4.1 Для психолога

**Начало вопросника:**
1. Пользователь заходит на страницу вопросника (`/account/certification/questionnaires/[id]`)
2. Проверяется, есть ли незавершённая попытка (`status = IN_PROGRESS`)
3. Если есть — восстанавливается
4. Если нет и есть доступные попытки — создаётся новая:
   - Из `questionsPool` выбираются случайные `questionsCount` вопросов
   - Сохраняются в `selectedQuestions`
   - `startedAt` = текущее время
   - `status = IN_PROGRESS`

**Прохождение:**
- Вопросы показываются последовательно
- Каждый вопрос — текстовое поле (max 2000 символов, min 100 — проверка на клиенте)
- Таймер отображается вверху (если `timeLimit` задан)
- Кнопка "Далее" сохраняет ответ в `answers` и показывает следующий вопрос
- При истечении таймера — попытка автоматически помечается как `EXPIRED`, ответы не отправляются

**Завершение:**
- После последнего вопроса — кнопка "Завершить"
- Сохраняются все ответы, `finishedAt` = текущее время, `timeSpent` = разница между `startedAt` и `finishedAt`
- `status = COMPLETED`
- Создаётся `QuestionnaireSubmission` (отправка на проверку)
- Пользователь видит сообщение: "Ответы отправлены на проверку"

**Статусы для пользователя:**
- Нет попыток > кнопка "Купить попытку" (если есть цена разблокировки в `Challenge.price`)
- Есть `IN_PROGRESS` > кнопка "Продолжить"
- Есть `COMPLETED` без `QuestionnaireSubmission` (не отправлено) > кнопка "Отправить на проверку"
- Есть `SUBMITTED`/`REVIEWING` > статус "На проверке"
- `APPROVED` > статус "Пройдено ?"
- `REJECTED` > статус "Отклонено ?" + комментарий

### 4.2 Для супервизора

**Логика полностью повторяет проверку работ:**

- **Доступные вопросники:** `status = SUBMITTED` AND `reviewerId = NULL` AND нет проверки от этого супервизора
- **Взятие:** создаётся `QuestionnaireReview` со `status = TAKEN`, `submission.reviewerId` проставляется, `status = REVIEWING`
- **Проверка:** супервизор видит все вопросы и ответы психолога (анонимно)
- **Вердикт:** `APPROVED` или `REJECTED` (при REJECTED — комментарий обязателен)
- **После вердикта:**
  - Обновляются счётчики `approvedCount`/`rejectedCount`
  - Если порог достигнут — `status = APPROVED`/`REJECTED`, начисляются деньги супервизору
  - Если нет — `status = SUBMITTED`, `reviewerId = NULL` (возврат в пул)

### 4.3 В сертификации

При проверке выполнения требований:
- Если `challenge.type = QUESTIONNAIRE` > проверить `QuestionnaireSubmission` с `status = APPROVED`

## 5. Админ-панель

### 5.1 Создание/редактирование вопросника

**Раздел:** `/admin/challenges`

**Поля:**

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| Название | Текст | Да | Заголовок вопросника |
| Описание | Textarea | Нет | Описание для психолога (показывается до начала) |
| Инструкция для супервизора | Textarea | Нет | Инструкция по проверке |
| Банк вопросов | Json-редактор | Да | Список вопросов (каждый с `text` и `order`) |
| Количество вопросов | Число | Да | Сколько вопросов выдаётся за попытку |
| Лимит времени | Число (мин) | Нет | null = без лимита |
| Бесплатных попыток | Число | Да | По умолчанию 1 |
| Цена разблокировки | Число (руб) | Нет | Цена за дополнительную попытку |
| Цена проверки для супервизора | Число (руб) | Да | Начисляется за проверку |
| Активно | Чекбокс | Нет | По умолчанию true |

### 5.2 Редактор банка вопросов

Простой интерфейс: список вопросов с возможностью добавлять/удалять/сортировать.

```json
[
  { "text": "Опишите вашу стратегию работы с клиентом в ситуации...", "order": 1 },
  { "text": "Какие методы вы используете для работы с тревогой?", "order": 2 }
]
```
