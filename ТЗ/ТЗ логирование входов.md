## ТЗ: Система логирования авторизаций

### 1. Модель данных

Создать таблицу `AccessLog`:

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| id | String (cuid) | Да | Первичный ключ |
| sessionId | String? | Нет | ID сессии (для SUCCESS/LOGOUT) |
| userId | String? | Нет | ID психолога (для SUCCESS/LOGOUT) |
| clientId | String? | Нет | ID клиента (для SUCCESS/LOGOUT) |
| userType | String? | Нет | "psychologist" / "client" (для SUCCESS) |
| eventType | String | Да | "LOGIN_SUCCESS", "LOGIN_FAILED", "LOGOUT" |
| emailHash | String? | Нет | SHA256(email) для поиска |
| ipAddress | String | Да | IP адрес |
| userAgent | String? | Нет | User-Agent браузера |
| reason | String? | Нет | Причина (для FAILED: "user_not_found", "wrong_type", "expired_token", "consent_required") |
| createdAt | DateTime | Да | По умолчанию now() |

**Индексы:** 
- `createdAt`
- `userId`, `clientId`
- `emailHash`
- `ipAddress`

### 2. Логика записи

**При LOGIN_SUCCESS (после успешной верификации токена):**
- Записываем: `userId` или `clientId`, `userType`, `sessionId`, `eventType = "LOGIN_SUCCESS"`, `ipAddress`, `userAgent`
userType - психолог или клиент

**При LOGOUT:**
- Записываем: `userId` или `clientId`, `sessionId`, `eventType = "LOGOUT"`, `ipAddress`, `userAgent`

**При LOGIN_FAILED:**
- Причина 1: `user_not_found` — email не найден в соответствующей таблице
- Причина 2: `wrong_type` — пользователь существует, но тип не совпадает (психолог пытается войти как клиент)
- Причина 3: `expired_token` — токен протух
- Причина 4: `consent_required` — не дано согласие на ПД
- Записываем: `emailHash`, `eventType = "LOGIN_FAILED"`, `reason`, `ipAddress`, `userAgent`

### 3. Интеграция

**Где вызывать запись:**

1. **В API верификации** (`/api/auth/verify`):
   - При успехе → `LOGIN_SUCCESS`
   - При ошибке (пользователь не найден, тип не совпал, согласие не дано) → `LOGIN_FAILED` с соответствующей причиной

2. **В API логаута** (`/api/auth/logout`):
   - При вызове → `LOGOUT`

### 4. Очистка логов

- Автоматическое удаление записей старше 1 года
- Еженедельная задача (cron)

### 5. Админка (опционально)

Раздел `/admin/logs/access`:
- Фильтр по: дате, eventType, email (поиск по хэшу), IP
- Просмотр списка
- Доступ только у администраторов
