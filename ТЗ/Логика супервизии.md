# Техническое задание: Система проверки квалификационных работ (WorkSubmission)

## 1. Общее описание

Система позволяет психологам отправлять квалификационные работы на проверку, а супервизорам — проверять их. Проверка может требовать multiple reviews (например, 2 из 3 супервизоров должны одобрить работу).

---

## 2. Модели данных (Prisma)

### 2.1 WorkSubmission (отправленная работа)

```prisma
model WorkSubmission {
  id             String        @id @default(cuid())
  challengeId    String
  userId         String
  videoUrl       String        // ссылка на видео сессии
  transcriptUrl  String        // ссылка на расшифровку
  status         WorkStatus    @default(SUBMITTED)
  submittedAt    DateTime      @default(now())
  approvedCount  Int           @default(0)
  rejectedCount  Int           @default(0)
  currentReviewerId String?     // id супервизора, кто сейчас проверяет
  
  challenge      Challenge     @relation(fields: [challengeId], references: [id])
  user           User          @relation(fields: [userId], references: [id])
  currentReviewer User?        @relation(fields: [currentReviewerId], references: [id])
  reviews        WorkReview[]
}

enum WorkStatus {
  SUBMITTED   // работа в пуле, можно взять на проверку
  REVIEWING   // кто-то проверяет (currentReviewerId не null)
  APPROVED    // одобрена (approvedCount >= reviewsToPass)
  REJECTED    // отклонена (rejectedCount > requiredReviews - reviewsToPass)
}
```

### 2.2 WorkReview (запись о проверке)

```prisma
model WorkReview {
  id           String        @id @default(cuid())
  submissionId String
  supervisorId String
  status       WorkReviewStatus @default(TAKEN)
  verdict      ReviewVerdict?
  comment      String?       @db.Text  // комментарий для психолога (при REJECTED)
  createdAt    DateTime      @default(now())
  resolvedAt   DateTime?              // когда завершена (COMPLETED)
  
  submission WorkSubmission @relation(fields: [submissionId], references: [id])
  supervisor User           @relation(fields: [supervisorId], references: [id])
  
  @@unique([submissionId, supervisorId])
}

enum WorkReviewStatus {
  TAKEN      // взял, проверяет
  COMPLETED  // вынес вердикт
  CANCELLED  // отказался от проверки
}

enum ReviewVerdict {
  APPROVED
  REJECTED
}
```

### 2.3 Дополнение в Challenge (уже есть)

```prisma
model WorkChallenge {
  id              String   @id @default(cuid())
  challengeId     String   @unique
  instructions    String?  @db.Text
  requiredReviews Int      @default(1)   // сколько всего проверок нужно
  reviewsToPass   Int      @default(1)   // сколько APPROVED нужно для сдачи
  // reviewPrice удалён, цена теперь в Challenge.price
}
```

## 3. Потоки данных и логика

### 3.1 Отправка работы (психолог)

**Вход:** challengeId, videoUrl, transcriptUrl  
**Выход:** WorkSubmission

**Логика:**
1. Проверить, есть ли уже отправленная работа с `status IN (SUBMITTED, REVIEWING)`
2. Если есть — вернуть ошибку "У вас уже есть активная работа"
3. Если нет — создать `WorkSubmission`:
   - `status = SUBMITTED`
   - `approvedCount = 0`, `rejectedCount = 0`
   - `currentReviewerId = NULL`
4. Отправить уведомление супервизорам (опционально)

### 3.2 Получение списка доступных работ (супервизор)

**Условия отбора:**
```sql
WHERE status = 'SUBMITTED' 
  AND currentReviewerId IS NULL
  AND id NOT IN (
    SELECT submissionId FROM WorkReview 
    WHERE supervisorId = текущий_супервизор
  )
```

**То есть:** работа не должна проверяться сейчас, и супервизор ещё не взаимодействовал с ней (не брал, не проверял, не отказывался).

### 3.3 Взятие работы (супервизор)

**Вход:** submissionId, supervisorId  
**Выход:** обновлённая WorkSubmission

**Логика:**
1. Проверить, что работа в статусе `SUBMITTED` и `currentReviewerId = NULL`
2. Проверить, что у супервизора нет `WorkReview` для этой работы
3. В транзакции:
   - Создать `WorkReview` со `status = TAKEN`
   - Обновить `WorkSubmission`: `status = REVIEWING`, `currentReviewerId = supervisorId`

### 3.4 Вынесение вердикта (супервизор)

**Вход:** submissionId, supervisorId, verdict (APPROVED/REJECTED), comment (только для REJECTED)  
**Выход:** обновлённая WorkSubmission

**Логика:**
1. Проверить, что `currentReviewerId = supervisorId` и `status = REVIEWING`
2. В транзакции:
   - Обновить `WorkReview`: `status = COMPLETED`, `verdict = verdict`, `comment = comment` (если REJECTED), `resolvedAt = now()`
   - Обновить счётчики в `WorkSubmission`:
     - Если `APPROVED` > `approvedCount++`
     - Если `REJECTED` > `rejectedCount++`
   - Очистить `currentReviewerId = NULL`
3. **Проверка порога:**
   ```typescript
   const challenge = await getChallenge(submission.challengeId)
   const requiredReviews = challenge.work.requiredReviews
   const reviewsToPass = challenge.work.reviewsToPass
   
   if (approvedCount >= reviewsToPass) {
     status = 'APPROVED'
   } 
   else if (rejectedCount > (requiredReviews - reviewsToPass)) {
     status = 'REJECTED'
   }
   else {
     status = 'SUBMITTED'  // возвращаем в пул
   }
   ```
4. Если статус стал `APPROVED` или `REJECTED`:
   - Начислить деньги супервизору (за каждую проверку) — через `creditSupervisor` из billing
   - Отправить уведомление психологу о результате

### 3.5 Отказ от проверки (супервизор)

**Вход:** submissionId, supervisorId, cancelReason (опционально)  
**Выход:** обновлённая WorkSubmission

**Логика:**
1. Проверить, что `currentReviewerId = supervisorId` и `status = REVIEWING`
2. В транзакции:
   - Обновить `WorkReview`: `status = CANCELLED`, `comment = cancelReason`, `resolvedAt = now()`
   - Обновить `WorkSubmission`: `currentReviewerId = NULL`, `status = SUBMITTED`
   - **Счётчики не трогаем!**

### 3.6 Получение истории супервизора

**Вход:** supervisorId  
**Выход:** список WorkReview с `status IN (COMPLETED, CANCELLED)`

**Отображение:**
- `COMPLETED` + `APPROVED` > "Одобрено, дата, начислено X ?"
- `COMPLETED` + `REJECTED` > "Отклонено, дата"
- `CANCELLED` > "Отказался, дата"

### 3.7 Получение комментариев для психолога

**Вход:** submissionId (при статусе REJECTED)  
**Выход:** список комментариев из `WorkReview`, где `verdict = REJECTED`

**Важно:** Комментарии выводятся **без указания супервизора** (анонимно).

## 4. API Endpoints (Server Actions)

### 4.1 Для психолога

| Action | Вход | Выход |
|--------|------|-------|
| `submitWork(challengeId, videoUrl, transcriptUrl)` | challengeId, ссылки | WorkSubmission |
| `getMyWorkSubmissions(challengeId?)` | опционально challengeId | список WorkSubmission |
| `updateWorkSubmission(submissionId, videoUrl, transcriptUrl)` | submissionId, новые ссылки | WorkSubmission (только если status = SUBMITTED) |

### 4.2 Для супервизора

| Action | Вход | Выход |
|--------|------|-------|
| `getAvailableSubmissions()` | supervisorId | список WorkSubmission (условия из п.3.2) |
| `takeSubmission(submissionId)` | submissionId | WorkSubmission |
| `reviewSubmission(submissionId, verdict, comment?)` | submissionId, verdict, comment | WorkSubmission |
| `cancelReview(submissionId, cancelReason?)` | submissionId, cancelReason | WorkSubmission |
| `getMyReviewHistory()` | supervisorId | список WorkReview |

### 4.3 Для админа

| Action | Вход | Выход |
|--------|------|-------|
| `getAllSubmissions(filters)` | filters (status, challengeId, userId) | список WorkSubmission |
| `forceApproveSubmission(submissionId)` | submissionId | WorkSubmission |
| `forceRejectSubmission(submissionId, comment)` | submissionId, comment | WorkSubmission |

## 5. Интерфейсные требования

### 5.2 Для супервизора (/account/supervision)

**Три вкладки:**

| Вкладка | Условие | Действия |
|---------|---------|----------|
| **Доступные** | `status = SUBMITTED` AND `currentReviewerId = NULL` AND нет `WorkReview` | [Взять] |
| **На проверке** | `status = REVIEWING` AND `currentReviewerId = текущий` | [Проверить] [Отказаться] |
| **История** | `WorkReview` где `supervisorId = текущий` и `status != TAKEN` | просмотр |

**Страница проверки:**
- Показывает ссылки на видео и расшифровку (открываются в новом окне)
- Показывает инструкцию из `WorkChallenge.instructions`
- Кнопки: [Одобрить] [Отклонить] (при отклонении — поле для комментария)[Отказаться]

## 6. Начисление денег супервизорам

- Цена за проверку хранится в `Challenge.price` (в копейках)
- При `APPROVED` или `REJECTED` (любой вердикт, кроме отказа) — начисляем супервизору сумму
Каждый супервизор получает оплату только за свою проверку, и только один раз.

Супервизор взял работу > проверил > вынес вердикт (APPROVED или REJECTED) > получил оплату

Если работа не принята с первого раза (требуется больше проверок) и возвращается в пул, то следующий супервизор, который её проверит, тоже получит оплату за свою проверку

Один и тот же супервизор не может проверить работу дважды (уникальность [submissionId, supervisorId]), поэтому дважды не заплатит

Пример:
Работа требует 2 проверки (requiredReviews = 2, reviewsToPass = 2)

Супервизор А взял > APPROVED > получил 500 ?

Работа вернулась в пул (нужна ещё одна проверка)

Супервизор Б взял > APPROVED > получил 500 ?

Работа APPROVED

Итог: два супервизора, две оплаты. Всё честно.

В случае REJECTED:
Супервизор А взял > REJECTED > получил 500 ? (он всё равно проверил работу)

Работа REJECTED (если порог достигнут) или возвращается в пул (если ещё можно получить APPROVED)
---

## 7. Ограничения и проверки

1. **Один супервизор не может проверить одну работу дважды** — проверка через `@@unique([submissionId, supervisorId])`
2. **Одновременно работу может проверять только один супервизор** — через `currentReviewerId`
3. **Супервизор не может взять работу, если уже взаимодействовал с ней** (TAKEN, COMPLETED, CANCELLED)
4. **Психолог может редактировать работу только в статусе `SUBMITTED`**
5. **При `REJECTED` комментарий обязателен** (валидация на уровне сервера)
