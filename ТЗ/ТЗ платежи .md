## ТЗ: Интеграция платежей Т-Банка (интернет-эквайринг)

### 1. Общие требования

Разработать модуль приема платежей через Т-Банк (ранее Тинькофф) для пополнения внутреннего баланса пользователей. Интеграция выполняется через **API интернет-эквайринга Т-Банка** (Т-Касса) с использованием **платежной формы**, на которую перенаправляется пользователь после создания платежа.

**Поддерживаемые способы оплаты (из коробки платежной формы):**
- Банковские карты (Visa, Mastercard, МИР)
- СБП (Система быстрых платежей)
- T-Pay
- Mir Pay
- Долями (BNPL)
- SberPay
- Рассрочка

**Важно:** Используется **одностадийная схема** — деньги списываются сразу после оплаты, без холдирования. Это стандартный вариант для пополнения баланса.

### 2. Модели данных (Prisma)

```prisma
// Таблица платежей
model Payment {
  id           String   @id @default(cuid())
  userId       String
  amount       Int      // сумма в копейках (целое число)
  status       String   // "pending", "succeeded", "failed", "refunded"
  provider     String   // "tbank"
  providerId   String?  // PaymentId от Т-Банка
  orderId      String   @unique // наш внутренний ID заказа (генерация при создании)
  description  String?  // "Пополнение баланса"
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt

  user         User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
  @@index([status])
  @@index([orderId])
}
```

**О соответствии закону:**
- Поле `status` фиксирует все состояния платежа, необходимо для аудита и отчетности (требование 54-ФЗ)
- `orderId` уникален — гарантирует идемпотентность (защита от повторного списания)
- Сумма в копейках — стандарт банковских API, избегает проблем с плавающей точкой
- `providerId` (PaymentId от Т-Банка) нужен для сверки и возвратов

### 3. Формирование токена (подписи запроса)

Токен — это строка в запросе, в которой мерчант шифрует данные с помощью пароля.

**Алгоритм формирования токена (метод Init):**

1. Собрать массив передаваемых параметров в виде пар `ключ:значение` **только для параметров корневого объекта** (вложенные объекты и массивы не участвуют):
```json
[
  {"TerminalKey": "MerchantTerminalKey"},
  {"Amount": "19200"},
  {"OrderId": "00000"},
  {"Description": "Подарочная карта на 1000 рублей"}
]
```

2. Добавить в массив пару `{"Password": "значение_пароля"}`:
```json
[
  {"TerminalKey": "MerchantTerminalKey"},
  {"Amount": "19200"},
  {"OrderId": "00000"},
  {"Description": "Подарочная карта на 1000 рублей"},
  {"Password": "11111111111111"}
]
```

3. **Отсортировать массив по алфавиту по ключу**:
```json
[
  {"Amount": "19200"},
  {"Description": "Подарочная карта на 1000 рублей"},
  {"OrderId": "00000"},
  {"Password": "11111111111111"},
  {"TerminalKey": "MerchantTerminalKey"}
]
```

4. **Конкатенировать только значения пар в одну строку**:
```
19200Подарочная карта на 1000 рублей0000011111111111111MerchantTerminalKey
```

5. Применить к строке хеш-функцию SHA-256 (с поддержкой UTF-8):
```
72dd466f8ace0a37a1f740ce5fb78101712bc0665d91a8108c7c8a0ccd426db2
```

6. Добавить получившийся результат в значение параметра `Token` в тело запроса.

**Формула в коде (пример для справки):**
```python
# Не для копирования, для понимания логики
def generate_token(payload: dict, password: str) -> str:
    token_data = {**payload, "Password": password}
    token_str = ''.join([str(token_data[key]) for key in sorted(token_data.keys()) 
                         if not isinstance(token_data[key], dict)])
    return sha256(token_str.encode("utf-8")).hexdigest()
```

**Как проверить корректность токена:** В личном кабинете интернет-эквайринга перейдите в раздел Операции, выберите нужный заказ и в блоке Дополнительная информация о заказе посмотрите на значение поля `inittokenisvalid`:
- `true` — токен валидный
- `false` — токен некорректный

### 6. API-роуты (App Router)

#### 6.1. Создание платежа — `app/api/payments/create/route.ts`

**Метод:** POST

**Тело запроса:**
```json
{
  "amount": 50000  // сумма в копейках (500 рублей)
}
```

**Логика:**
1. Получить текущего пользователя (getCurrentUser)
2. Валидация суммы: минимальная 5000 копеек (50 руб), максимальная 10000000 (100 000 руб)
3. Сгенерировать уникальный `OrderId` (например, `PAY_{timestamp}_{userId}_{random}`)
4. Создать запись Payment в БД со статусом `pending`
5. Сформировать токен (подпись) по алгоритму из раздела 3
6. Вызвать метод Init Т-Банка с параметрами:
   - `TerminalKey` — из .env
   - `Amount` — сумма в копейках
   - `OrderId` — сгенерированный
   - `Description` — "Пополнение баланса"
   - `Language` — "ru"
   - `Token` — сформированный токен
   - `SuccessURL` — URL для возврата после успешной оплаты
   - `FailURL` — URL для возврата после ошибки
   - `NotificationURL` — `TBANK_WEBHOOK_URL` из .env
7. Получить `PaymentId` и `PaymentURL` из ответа Т-Банка
8. Обновить запись Payment: `providerId = PaymentId`
9. Вернуть клиенту `{ paymentUrl: PaymentURL }`

#### 6.2. Вебхук — `app/api/payments/webhook/route.ts`

**Метод:** POST

**Тело вебхука (пример от Т-Банка):**
```json
{
  "TerminalKey": "ваш_терминал",
  "OrderId": "PAY_1234567890_user123",
  "PaymentId": "1234567890",
  "Status": "CONFIRMED",
  "Amount": 50000,
  "Token": "подпись"
}
```

**Логика:**
1. **Проверить подпись вебхука** (обязательно! по тому же алгоритму, что и для Init)
2. Найти платеж в БД по `OrderId`
3. Если платеж уже имеет статус `succeeded` — вернуть OK (идемпотентность)
4. В зависимости от `Status`:
   - `CONFIRMED` или `AUTHORIZED` → успешная оплата
   - `REJECTED`, `CANCELLED` → ошибка
5. При успехе:
   - Обновить статус платежа на `succeeded`
   - Создать запись в Transaction (тип `DEPOSIT`, сумма в копейках)
   - Увеличить баланс пользователя (`User.balance += amount`)
6. Вернуть `{ "Status": "OK" }` (Т-Банк ожидает именно такой ответ)

#### 6.3. Проверка статуса — `app/api/payments/status/route.ts`

**Метод:** GET

**Параметры:** `orderId` (query)

**Логика:**
1. Найти платеж в БД
2. Вернуть `{ status, amount, createdAt }`

### 7. Server Actions

`lib/actions/payments.ts`:

```typescript
"use server";

export async function createPayment(amount: number) {
  // Валидация суммы
  if (amount < 5000) throw new Error("Минимальная сумма пополнения 50 ₽");
  if (amount > 10000000) throw new Error("Максимальная сумма пополнения 100 000 ₽");

  // Вызов API роута
  const response = await fetch(`${process.env.NEXT_PUBLIC_APP_URL}/api/payments/create`, {
    method: "POST",
    body: JSON.stringify({ amount }),
    headers: { "Content-Type": "application/json" }
  });

  const { paymentUrl } = await response.json();
  return { paymentUrl };
}
```
