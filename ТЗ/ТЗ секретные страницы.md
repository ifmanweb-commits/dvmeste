model SecretPage {
  id        String   @id @default(cuid())
  slug      String   @unique
  title     String
  filePath  String   // например "secret-pages/pa-characters/index.html"
  isActive  Boolean  @default(true)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([slug])
  @@index([isActive])
}

model UserAccess {
  id           String   @id @default(cuid())
  userId       String
  resourceType String   // "page", "challenge", "course", "feature"
  resourceId   String   // ID страницы, испытания, курса
  grantedBy    String   // "key_<keyId>" или "admin_<adminId>"
  grantedAt    DateTime @default(now())
  expiresAt    DateTime? // опционально
  createdAt    DateTime @default(now())

  @@unique([userId, resourceType, resourceId])
  @@index([userId])
  @@index([resourceType, resourceId])
  @@index([grantedBy])
}

model Key {
  id          String   @id @default(cuid())
  code        String   @unique
  actionsJson Json     // логика что даёт ключ
  maxUses     Int      @default(1)
  usedCount   Int      @default(0)
  expiresAt   DateTime?
  isActive    Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@index([code])
  @@index([isActive])
}
model KeyUse {
  id        String   @id @default(cuid())
  keyId     String
  userId    String
  usedAt    DateTime @default(now())
  key       Key      @relation(fields: [keyId], references: [id], onDelete: Cascade)
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([keyId, userId]) // один пользователь — один раз использовал ключ
  @@index([keyId])
  @@index([userId])
}

## ТЗ: API route для отдачи секретных страниц
Логика: пользователь вводит секретный урл.
Если всё хорошо и доступ у него есть - он открывается.
По сути, прокси-прослойка к реальному файлу, который мы загружали в сикрет пейджес.

### Расположение
`/app/secret-page/[id]/route.ts`

### Логика работы

**1. Получить параметр id из URL**
- Пример: `/secret-page/clx1234567890`
- id — это CUID из таблицы SecretPage

**2. Получить текущего пользователя**
- Взять сессию из куки через `getCurrentUser()`
- Если пользователь не авторизован — вернуть 401

**3. Найти страницу в БД**
- `prisma.secretPage.findUnique({ where: { id, isActive: true } })`
- Если не найдена — вернуть 404

**4. Проверить доступ**
- `prisma.userAccess.findFirst({ where: { userId: user.id, resourceType: "page", resourceId: id } })`
- Если записи нет — вернуть 403

**5. Прочитать файл с диска**
- Путь: `public/{filePath}` (filePath из БД)
- Через `fs.readFileSync` или `fs.promises.readFile`

**6. Вернуть HTML**
- `new Response(htmlContent, { headers: { "Content-Type": "text/html" } })`

### Обработка ошибок
- 401 — нет сессии
- 403 — нет доступа
- 404 — страница не найдена или не активна
- 500 — ошибка чтения файла

### Кэширование
- Заголовки: `Cache-Control: no-cache` (чтобы доступ отзывался мгновенно)

### Логирование (опционально)
- Записывать факт обращения (userId, pageId, timestamp) — можно потом, не в первой версии

## Выполнение ключа

Отдельный API route: `/api/key-active`

**Логика выполнения:**
1. Получить code из тела запроса
2. Найти ключ в БД (по code, isActive=true, expiresAt > now или null, usedCount < maxUses или maxUses=0)
3. Проверить, не использовал ли уже этот пользователь данный ключ (KeyUse)
4. Пройти по всем actions из actionsJson и выполнить каждое:
   - `grant_page_access` → добавить запись в UserAccess (grantedBy = "key_{keyId}")
   - `revoke_page_access` → удалить запись из UserAccess
   - `enroll_course` → добавить/обновить запись в UserCourse с нужным статусом
   - `unenroll_course` → удалить запись из UserCourse (или изменить статус)
   - `complete_challenge` → создать ChallengeAttempt с passed=true
   - `add_balance` → создать Transaction (тип EARNING или ADJUSTMENT)
   - `subtract_balance` → создать Transaction (тип ADJUSTMENT)
   - `add_attempts` → обновить ChallengeUserState (увеличить attemptsLeft)
5. Создать запись в KeyUse
6. Увеличить usedCount у Key на 1
7. Вернуть успех и список того, что сделано

**Где вызывается:** В ЛК на странице `/account/redeem-key` — форма отправляет POST запрос на этот API.
