Нужно реализовать систему бекапов для БД на основе node-cron (уже есть в проекте)
Написать скрипт, который делает дамп БД и кладет его в соответствующую папку бекапов. Она должна монтироваться как том для докера.
Сразу же нужно сжимать дамп с помощью gzip 

Примерно так
const filename = `db_backup_${timestamp}.sql.gz`;
const filepath = path.join(BACKUP_DIR, filename);
const command = `pg_dump ${DB_URL} | gzip > ${filepath}`;

Запускать скрипт каждый день ночью.
Удалять старые бекапы, хранить только последние 30

1. Где будет запускаться скрипт бэкапа?
Внутри Docker-контейнера приложения.

Это самый простой вариант, не требующий дополнительных сервисов. pg_dump нужно будет установить в контейнере.

2. Какая СУБД используется? Где находится?
PostgreSQL. БД будет в отдельном контейнере (postgres), но в одной Docker-сети с приложением. Поэтому из контейнера app БД доступна по имени postgres:5432.

3. Путь для хранения бэкапов
Внутри контейнера: /app/backups

На хосте: ./backups (рядом с docker-compose.yml)

4. Время запуска
Каждый день в 3:30 утра

5. Удаление старых бэкапов
Хранить последние 30 файлов (по количеству). Проще и надёжнее, чем по дате — не нужно парсить даты из имён, просто сортировка по имени файла.

Файлы называются с датой, например backup_2025-01-27_030001.sql.gz. Сортировка по имени даст правильный порядок.

6. Логирование
Достаточно console.log. Docker сам соберёт логи, их можно будет посмотреть через docker compose logs app.

Логи писать в формате:

✅ Backup created: backup_2025-01-27_030001.sql.gz (size: 2.3MB)

❌ Backup failed: ...

8. Переменная DATABASE_URL
Да, используем существующую DATABASE_URL. Она уже указывает на PostgreSQL внутри Docker-сети.
