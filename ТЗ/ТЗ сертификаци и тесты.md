## 📋 ТЗ: Система сертификации и тестов

---

## 1. Общая информация

**Проект:** Давай вместе — каталог психологов  
**Технологии:** Next.js 16 (App Router), Prisma, Tailwind CSS  
**Тип задачи:** Реализация системы сертификации психологов через прохождение тестов

---

## 2. Модели данных (Prisma)

### 2.1. Challenge (испытание)

```prisma
enum ChallengeType {
  TEST
  WORK
}

model Challenge {
  id          String        @id @default(cuid())
  slug        String        @unique
  title       String
  description String?
  type        ChallengeType
  isActive    Boolean       @default(true)
  createdAt   DateTime      @default(now())
  updatedAt   DateTime      @updatedAt

  test        TestChallenge?
  work        WorkChallenge?
  requirements CertificationRequirement[]
  attempts     ChallengeAttempt[]
  userStates   ChallengeUserState[]
}
```

**Пояснения:**
- `slug` — уникальный идентификатор для URL (например, `ethics-test`)
- `type` — определяет, тест это или квалификационная работа
- `isActive` — если false, тест не показывается пользователям

---

### 2.2. TestChallenge (специфика теста)

```prisma
model TestChallenge {
  id            String   @id @default(cuid())
  challengeId   String   @unique
  questionsPool Json     // банк вопросов
  questionsCount Int     // сколько вопросов в тесте
  passingScore  Int      // сколько правильных нужно для сдачи
  timeLimit     Int?     // минут (null = без лимита)
  freeAttempts  Int      @default(2)
  unlockPrice   Int?     // цена разблокировки (в копейках, null = нельзя купить)

  challenge     Challenge @relation(fields: [challengeId], references: [id], onDelete: Cascade)
}
```

**Пояснения:**
- `questionsPool` — JSON с вопросами (формат ниже)
- `questionsCount` — количество вопросов, которое попадает в тест (случайная выборка из пула)
- `passingScore` — количество правильных ответов для сдачи (не процент!)
- `freeAttempts` — сколько бесплатных попыток даётся пользователю
- `unlockPrice` — цена покупки дополнительной попытки (в копейках, например 50000 = 500 руб.)

---

### 2.3. WorkChallenge (квалификационная работа — пока не реализуется)

```prisma

  challengeId     String   @unique
  requiredReviews Int      @default(1)
  reviewsToPass   Int      @default(1)
  reviewPrice     Int?

  challenge       Challenge @relation(fields: [challengeId], references: [id], onDelete: Cascade)
}
```

---

### 2.4. ChallengeAttempt (попытка прохождения)

```prisma
enum AttemptStatus {
  IN_PROGRESS
  COMPLETED
}

model ChallengeAttempt {
  id          String        @id @default(cuid())
  challengeId String
  userId      String
  status      AttemptStatus @default(IN_PROGRESS)
  passed      Boolean?
  startedAt   DateTime?
  finishedAt  DateTime?
  
  selectedQuestionIndices Json?
  answers                Json?
  score                  Int?
  
  createdAt   DateTime      @default(now())
  updatedAt   DateTime      @updatedAt

  challenge   Challenge     @relation(fields: [challengeId], references: [id])
  user        User          @relation(fields: [userId], references: [id])
}
```

**Пояснения:**
- `status` — `IN_PROGRESS` (можно продолжить), `COMPLETED` (завершена)
- `passed` — true (сдан), false (не сдан), null (ещё не завершён)
- `selectedQuestionIndices` — индексы вопросов, выбранных для этого теста (из пула)
- `answers` — ответы пользователя: `{ "0": [2], "1": [0,3] }` (индекс вопроса → массив индексов ответов)
- `score` — количество правильных ответов

---

### 2.5. ChallengeUserState (состояние пользователя)

```prisma
model ChallengeUserState {
  id          String   @id @default(cuid())
  challengeId String
  userId      String
  attemptsLeft Int      // сколько попыток осталось
  updatedAt   DateTime @updatedAt

  challenge   Challenge @relation(fields: [challengeId], references: [id])
  user        User      @relation(fields: [userId], references: [id])

  @@unique([challengeId, userId])
}
```

**Пояснения:**
- Создаётся при первом обращении пользователя к тесту
- `attemptsLeft` = `freeAttempts` + количество купленных попыток
- Уменьшается при каждой неудачной попытке
- Не уменьшается при успешной сдаче

### 2.6. Certification (программа сертификации)

model Certification {

  updatedAt   DateTime @updatedAt

## 3. Формат JSON для вопросов

```json
{
  "questionsPool": [
    {
      "text": "Клиентка признаётся, что изменила мужу. Как этично реагировать?",
      "type": "single",
      "options": [
        "Пожурить клиентку",
        "Сказать, что это нормально",
        "Сфокусироваться на её чувствах",
        "Рекомендовать развод"
      ],
      "correct": [2],
      "explanation": "Этично работать с чувствами клиентки, не осуждая её выбор."
    },
    {
      "text": "Какие методы имеют доказательную базу при тревоге? (выберите все)",
      "type": "multiple",
      "options": [
        "КПТ",
        "Гештальт-терапия",
        "Психоанализ",
        "EMDR"
      ],
      "correct": [0, 3],
      "explanation": "КПТ и EMDR имеют наибольшую доказательную базу для работы с тревогой."
    }
  ]
}
```

**Правила валидации JSON:**
- У каждого вопроса должно быть поле `text`
- `type` — `"single"` или `"multiple"`
- `options` — массив строк, минимум 2 элемента
- `correct` — массив индексов правильных ответов (все индексы должны быть в пределах `options`)
- `explanation` — опционально, может быть пустой строкой

## 4. Потоки данных

### 4.1. Создание теста (админ)

**Страница:** `/admin/challenges/new`

**Шаг 1. Основная информация:**
- Название (обязательно)
- Slug (генерируется из названия, можно редактировать)
- Описание
- Тип: выбираем "Тест"

**Шаг 2. Настройки теста:**
- Количество вопросов в тесте (например, 10)
- Проходной балл (например, 7 правильных)
- Лимит времени (минуты, 0 = без лимита)
- Бесплатных попыток (например, 2)
- Цена разблокировки (рубли, 0 = бесплатно)

**Шаг 3. Банк вопросов:**

Редактор с возможностью:
- Добавлять/удалять вопросы
- Редактировать текст вопроса, варианты, правильные ответы, пояснение
- Выбирать тип вопроса (один ответ / несколько)
- **Импорт JSON** — вставить JSON, система валидирует и загружает в редактор
- **Экспорт JSON** — скопировать текущий конфиг

**Сохранение:**
- Создаётся `Challenge` с типом `TEST`
- Создаётся `TestChallenge` с привязкой

---

### 4.2. Создание сертификации (админ)

**Страница:** `/admin/certifications/new`

- Название, slug, описание
- Добавление требований: выбираем существующие `Challenge` (тесты)
- Порядок отображения (можно менять)

---

### 4.3. Просмотр сертификаций (психолог)

**Страница:** `/account/certification`

- Список доступных сертификаций
- Для каждой:
  - Название, описание
  - Прогресс: сколько требований выполнено
  - Кнопка "Подробнее" → страница программы

---

### 4.4. Страница программы

**Страница:** `/account/certification/[slug]`

- Список требований (испытаний) в порядке `order`
- Для каждого требования:
  - Название
  - Статус: не пройдено / пройдено
  - Если тест:
    - Кнопка "Пройти"
    - Количество оставшихся попыток
    - Если попыток нет — кнопка "Разблокировать" с ценой

---

### 4.5. Страница теста

**Страница:** `/account/challenge/[slug]`

**При загрузке:**
1. Получаем `Challenge` и `TestChallenge`
2. Находим или создаём `ChallengeUserState` с `attemptsLeft = freeAttempts`
3. Проверяем, есть ли у пользователя незавершённая попытка (`status = IN_PROGRESS`):
   - Если есть — предлагаем продолжить
   - Если нет — показываем кнопку "Начать тест"

**При нажатии "Начать":**
1. Проверяем `attemptsLeft > 0`
2. Создаём `ChallengeAttempt`:
   - `status = IN_PROGRESS`
   - `startedAt = now()`
   - Выбираем случайные `questionsCount` индексов из `questionsPool`
   - Сохраняем в `selectedQuestionIndices`
3. Возвращаем клиенту первый вопрос (без правильного ответа)

---

### 4.6. Прохождение теста

**API роуты:**

| Роут | Метод | Назначение |
|------|-------|------------|
| `/api/challenge/:attemptId/next` | GET | Получить следующий вопрос |
| `/api/challenge/:attemptId/answer` | POST | Сохранить ответ |
| `/api/challenge/:attemptId/finish` | POST | Завершить тест |
| `/api/challenge/:attemptId/status` | GET | Получить текущее состояние (для восстановления) |

**Ответ на вопрос (GET):**
```json
{
  "questionIndex": 0,
  "text": "Клиентка признаётся...",
  "type": "single",
  "options": ["...", "...", "...", "..."]
}
```

**Сохранение ответа (POST):**
```json
{
  "questionIndex": 0,
  "answers": [2]
}
```

**Завершение:**
1. Сервер проверяет время (если истекло → `status = COMPLETED`, `passed = false`)
2. Сравнивает ответы с правильными из `questionsPool`
3. Считает `score`
4. Если `score >= passingScore` → `passed = true`, иначе `false`
5. Сохраняет результат
6. Если `passed = false` → уменьшает `attemptsLeft` в `ChallengeUserState`
7. Если `passed = true` → не меняет `attemptsLeft` (тест считается сданным)

---

### 4.7. Восстановление теста

Если пользователь:
- Перезагрузил страницу
- Закрыл вкладку
- Перешёл на другой сайт и вернулся

**Процесс:**
1. При загрузке страницы клиент делает запрос `GET /api/challenge/:attemptId/status`
2. Сервер возвращает:
   - `status` (IN_PROGRESS / COMPLETED)
   - Оставшееся время (если есть)
   - Список вопросов (без правильных ответов)
   - Уже сохранённые ответы
3. Клиент восстанавливает состояние

---

### 4.8. Разблокировка (оплата)

1. Пользователь нажимает "Разблокировать"
2. Оплата через Т-Кассу
3. После успешной оплаты:
   - Увеличиваем `attemptsLeft` в `ChallengeUserState`
   - Записываем транзакцию в историю (отдельная таблица)
4. Пользователь может начать тест

---

### 4.9. Получение сертификации

Когда пользователь выполнил все требования:
1. Проверяем `CertificationRequirement`:
   - Для каждого `Challenge` есть успешная попытка (`passed = true`)
2. Создаём запись в `CertificationAward`
3. Отображаем бейдж в профиле
4. Если это сертификация уровня — обновляем `certificationLevel` в `User`

---

## 5. Импорт/экспорт JSON

### Импорт
1. Пользователь вставляет JSON в текстовое поле
2. Система валидирует:
   - Корректность JSON
   - Наличие полей `questionsPool`, `questionsCount`, `passingScore` (в самом тесте, не в JSON)
   - Каждый вопрос: `text`, `type`, `options`, `correct`
   - `options` — массив строк, минимум 2
   - `correct` — массив индексов в пределах `options`
3. Если валидация пройдена — данные загружаются в визуальный редактор
4. Лишние поля отбрасываются

### Экспорт
- Кнопка "Скопировать JSON"
- Формирует JSON только с `questionsPool` (без настроек теста)

- Цена разблокировки (рубли, 0 = бесплатно)

**Шаг 3. Банк вопросов:**

Редактор с возможностью:
- Добавлять/удалять вопросы
- Редактировать текст вопроса, варианты, правильные ответы, пояснение
- Выбирать тип вопроса (один ответ / несколько)
- **Импорт JSON** — вставить JSON, система валидирует и загружает в редактор
- **Экспорт JSON** — скопировать текущий конфиг

**Сохранение:**
- Создаётся `Challenge` с типом `TEST`
- Создаётся `TestChallenge` с привязкой

---

### 4.2. Создание сертификации (админ)

**Страница:** `/admin/certifications/new`

- Название, slug, описание
- Добавление требований: выбираем существующие `Challenge` (тесты)
- Порядок отображения (можно менять)

### 4.3. Просмотр сертификаций (психолог)

**Страница:** `/account/certification`

- Список доступных сертификаций
- Для каждой:
  - Название, описание
  - Прогресс: сколько требований выполнено
  - Кнопка "Подробнее" → страница программы

### 4.4. Страница программы

**Страница:** `/account/certification/[slug]`

- Список требований (испытаний) в порядке `order`
- Для каждого требования:
  - Название
  - Статус: не пройдено / пройдено
  - Если тест:
    - Кнопка "Пройти"
    - Количество оставшихся попыток
    - Если попыток нет — кнопка "Разблокировать" с ценой

### 4.5. Страница теста

**Страница:** `/account/challenge/[slug]`

**При загрузке:**
1. Получаем `Challenge` и `TestChallenge`
2. Находим или создаём `ChallengeUserState` с `attemptsLeft = freeAttempts`
3. Проверяем, есть ли у пользователя незавершённая попытка (`status = IN_PROGRESS`):
   - Если есть — предлагаем продолжить
   - Если нет — показываем кнопку "Начать тест"

**При нажатии "Начать":**
1. Проверяем `attemptsLeft > 0`
2. Создаём `ChallengeAttempt`:
   - `status = IN_PROGRESS`
   - `startedAt = now()`
   - Выбираем случайные `questionsCount` индексов из `questionsPool`
   - Сохраняем в `selectedQuestionIndices`
3. Возвращаем клиенту первый вопрос (без правильного ответа)

---

### 4.6. Прохождение теста

**API роуты:**

| Роут | Метод | Назначение |
|------|-------|------------|
| `/api/challenge/:attemptId/next` | GET | Получить следующий вопрос |
| `/api/challenge/:attemptId/answer` | POST | Сохранить ответ |
| `/api/challenge/:attemptId/finish` | POST | Завершить тест |
| `/api/challenge/:attemptId/status` | GET | Получить текущее состояние (для восстановления) |

**Ответ на вопрос (GET):**
```json
{
  "questionIndex": 0,
  "text": "Клиентка признаётся...",
  "type": "single",
  "options": ["...", "...", "...", "..."]
}
```

**Сохранение ответа (POST):**
```json
{
  "questionIndex": 0,
  "answers": [2]
}
```

**Завершение:**
1. Сервер проверяет время (если истекло → `status = COMPLETED`, `passed = false`)
2. Сравнивает ответы с правильными из `questionsPool`
3. Считает `score`
4. Если `score >= passingScore` → `passed = true`, иначе `false`
5. Сохраняет результат
6. Если `passed = false` → уменьшает `attemptsLeft` в `ChallengeUserState`
7. Если `passed = true` → не меняет `attemptsLeft` (тест считается сданным)

---

### 4.7. Восстановление теста

Если пользователь:
- Перезагрузил страницу
- Закрыл вкладку
- Перешёл на другой сайт и вернулся

**Процесс:**
1. При загрузке страницы клиент делает запрос `GET /api/challenge/:attemptId/status`
2. Сервер возвращает:
   - `status` (IN_PROGRESS / COMPLETED)
   - Оставшееся время (если есть)
   - Список вопросов (без правильных ответов)
   - Уже сохранённые ответы
3. Клиент восстанавливает состояние

---

### 4.8. Разблокировка (оплата)

1. Пользователь нажимает "Разблокировать"
2. Оплата через Т-Кассу
3. После успешной оплаты:
   - Увеличиваем `attemptsLeft` в `ChallengeUserState`
   - Записываем транзакцию в историю (отдельная таблица)
4. Пользователь может начать тест

---

### 4.9. Получение сертификации

Когда пользователь выполнил все требования:
1. Проверяем `CertificationRequirement`:
   - Для каждого `Challenge` есть успешная попытка (`passed = true`)
2. Создаём запись в `CertificationAward`
3. Отображаем бейдж в профиле
4. Если это сертификация уровня — обновляем `certificationLevel` в `User`

---

## 5. Импорт/экспорт JSON

### Импорт
1. Пользователь вставляет JSON в текстовое поле
2. Система валидирует:
   - Корректность JSON
   - Наличие полей `questionsPool`, `questionsCount`, `passingScore` (в самом тесте, не в JSON)
   - Каждый вопрос: `text`, `type`, `options`, `correct`
   - `options` — массив строк, минимум 2
   - `correct` — массив индексов в пределах `options`
3. Если валидация пройдена — данные загружаются в визуальный редактор
4. Лишние поля отбрасываются

### Экспорт
- Кнопка "Скопировать JSON"
- Формирует JSON только с `questionsPool` (без настроек теста)
