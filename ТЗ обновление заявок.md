📋 ТЗ: Обновление модели Lead (упрощение статусов)
1️⃣ Цель
Упростить систему статусов заявок. Заменить множественные статусы на 3 основных + отдельное поле resolution для фиксации исхода.

2️⃣ Текущее состояние
В таблице Lead есть записи (в том числе тестовые). При миграции старые данные можно удалить или преобразовать (по выбору).

3️⃣ Новая структура модели
prisma
enum LeadStatus {
  NEW
  ACCEPTED
  COMPLETED
}

enum LeadResolution {
  PSYCHOLOGIST_REJECTED  // психолог отказал сразу
  NO_CONTACT             // не удалось связаться
  NO_AGREEMENT           // связались, но не договорились
  CLIENT_DROPPED         // договорились, клиент пропал
  FREE_ONLY              // только бесплатная сессия
  PAID_COMPLETED         // были платные сессии
}

model Lead {
  id               String          @id @default(cuid())
  clientId         String
  psychologistId   String
  message          String?         @db.Text
  status           LeadStatus      @default(NEW)
  resolution       LeadResolution?
  statusChangedAt  DateTime?
  createdAt        DateTime        @default(now())
  viewedAt         DateTime?

  // остальные поля без изменений
  isSuspicious     Boolean         @default(false)
  suspiciousReason String?

  client           Client          @relation(fields: [clientId], references: [id])
  psychologist     User            @relation(fields: [psychologistId], references: [id])

  @@index([clientId])
  @@index([psychologistId])
  @@index([status])
  @@index([createdAt])
}
4️⃣ Миграция
Вариант без потери данных: Создать миграцию, которая:

Добавляет поле resolution

Преобразует старые статусы в новые:

NEW → NEW

ACCEPTED, CONTACTED, APPOINTMENT → ACCEPTED

FREE_SESSION, PAID_SESSION → COMPLETED + соответствующий resolution

REJECTED, NO_CONTACT, CLIENT_REJECTED, ARCHIVED → COMPLETED + resolution = PSYCHOLOGIST_REJECTED (для простоты)
