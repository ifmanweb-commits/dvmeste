**Напомню про теневой бан клиента:**

- В модели `Client` есть поле `isShadowBanned`
- Если `true` → новые заявки от этого клиента помечаются `isSuspicious = true`
- Психолог видит предупреждение в карточке заявки
- Клиент **не знает** о бане, форма работает как обычно

**Действие "Теневой бан клиента"** → просто ставим `isShadowBanned = true`

### 2️⃣ Страница списка заявок (`/admin/leads`)

#### 2.1 **Таблица заявок**
Над таблицей - фильтры (описаны ниже)
Колонки:
- Дата и время
- Психолог (ФИО, ссылка на его карточку в админке)
- Клиент (email, имя)
- Сообщение (первые 70 символов)
- Статус (бейдж: NEW / ACCEPTED / COMPLETED)
- Исход (resolution, если COMPLETED)
- Действия

В таблице действует пагинация по 50 строк. Пагинация должна корректно отрабатывать со включенными фильтрами. Например, "следующие 50 заявок этого психолога".

### Пагинация
Правильная логика:
Пользователь выбирает фильтр → формируется URL с query-параметрами:

text
/admin/leads?status=NEW&psychologistId=123&page=2
Серверный компонент читает параметры:

typescript
const { status, psychologistId, page = 1, limit = 50 } = searchParams
Запрос в БД с where и skip/take

Возвращаем только отфильтрованные и отпагинированные заявки

Клиент только отображает

#### 2.2 **Фильтры**

- Поиск по email клиента или имени психолога
- Фильтр по статусу (`NEW` / `ACCEPTED` / `COMPLETED`)
- Фильтр по исходу (resolution)
- Фильтр по дате (период)

#### 2.3 **Сортировка**

- По дате: от новых к старым (по умолчанию)
- По дате: от старых к новым (для выявления зависших заявок)

#### 2.4 **Действия в таблице**

- Клик по email клиента → показать все заявки этого клиента (фильтр)
- Клик по имени психолога → показать все заявки этого психолога (фильтр)
- Кнопка "Подробнее" → открывает детальную страницу заявки

**Действия модератора:**
